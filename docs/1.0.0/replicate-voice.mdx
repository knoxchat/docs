<MethodEndpoint
  method={"post"}
  path={"https://api.knoxstudio.ai/v1/voices/{voice_id}/replicate-to-isolated-environment"}
>
</MethodEndpoint>

`target_workspace_id` is required. Optional `preserve_voice_id` (default true). **Not billed**.

## Request

### Path Parameters

| Name | Type | Required | Description |
| ---- | ---- | ---- | ---- |
| voice_id | String | Yes | Voice ID. |

### Request Headers

| Name | Type | Required | Description |
| ---- | ---- | ---- | ---- |
| Authorization | String | Yes | `Bearer <token>` Knox API key. `xi-api-key` is also accepted. |
| Content-Type | String | Yes | `application/json` |

### Request Body

| Name | Type | Required | Description |
| ---- | ---- | ---- | ---- |
| target_workspace_id | String | Yes | Destination workspace in the same billing group. |
| preserve_voice_id | Boolean | No | Keep the same voice ID in the target residency. Default true. |

## cURL Example

```shell
curl -X POST https://api.knoxstudio.ai/v1/voices/voice_id/replicate-to-isolated-environment \
     -H "Authorization: Bearer $KNOXCHAT_API_KEY" \
     -H "Content-Type: application/json" \
     -d '{"target_workspace_id":"ws_123","preserve_voice_id":true}'
```

## Response

### Success Response (200)

JSON with the replicated `voice_id`.

## Error Responses

Validation uses HTTP `422`:

```json
{
  "detail": [
    {
      "loc": ["body", "field"],
      "msg": "…",
      "type": "value_error"
    }
  ]
}
```

Other errors use `{ "detail": "message" }`.

| Status | When |
| ------ | ---- |
| `400` | WebSocket path called without `Upgrade: websocket`. |
| `401` | Missing or invalid API key. |
| `402` | Insufficient credits. |
| `403` | Token is not allowed to use this model. |
| `404` | Resource not found. |
| `422` | Validation error. |
| `429` | Rate limit exceeded. |
| `500` | Internal server error. |
