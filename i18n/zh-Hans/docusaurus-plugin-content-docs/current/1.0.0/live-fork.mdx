把**已存储**的 Live 会话（创建时 `store: true`）分叉成继承历史的新对话。只有所有者可以分叉。分叉使用与源会话相同的上游 OpenAI 通道。

- **GET** 升级为 WebSocket。第一条消息仍必须是 `session.start`。分叉可覆盖的字段仅限 `store`、Responses 委派和 `audio.format`。
- **POST** 用 SDP offer 创建 WebRTC 分叉（JSON `{ "sdp", "session" }` 或原始 `application/sdp`）。

继承的设置（音色、instructions、委派模式）除非你发送允许的覆盖，否则保持不变。不能更改 `model`；分叉仍使用 `gpt-live-1`。

见 [GPT-Live](/live) 指南。

## 路径参数

| 名称 | 类型 | 必填 | 描述 |
| ---- | ---- | ---- | ---- |
| session_id | String | 是 | **已存储**源会话的 id。 |

## WebSocket 分叉

```javascript
import WebSocket from "ws";

const sourceId = "sess_…";
const ws = new WebSocket(
  `wss://api.knox.chat/v1/live/sessions/${sourceId}/fork`,
  { headers: { Authorization: "Bearer " + process.env.KNOX_API_KEY } }
);

ws.on("open", () => {
  ws.send(JSON.stringify({
    type: "session.start",
    session: { store: true },
  }));
});
```

非 WebSocket 的 GET 返回 `400`：请通过 WebSocket 连接 `/v1/live/sessions/{id}/fork`，或 POST 一个 WebRTC SDP offer。

## WebRTC 分叉

```shell
curl -s https://api.knox.chat/v1/live/sessions/sess_…/fork \
     -H "Authorization: Bearer $KNOXCHAT_API_KEY" \
     -H "Content-Type: application/json" \
     -d '{
  "sdp": "v=0\r\n…",
  "session": { "store": true }
}'
```

与 [创建](/1.0.0/live-create) 相同的 15 秒 WebRTC 预收。

## 错误响应

| 状态 | 何时 |
| ---- | ---- |
| `400` | 不是 WebSocket（GET）、缺少 SDP（POST），或分叉 session 无效。 |
| `401` | 缺少或无效的 Knox API key。 |
| `402` | 账户余额不大于 $0.01。 |
| `403` | Token 未被授权使用 `gpt-live-1`。 |
| `404` | 源会话不存在、未存储，或不属于当前用户。 |
| `502` | 上游分叉失败。 |
